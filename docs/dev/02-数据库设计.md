# 02 数据库设计（MySQL 8）

## 0. 通用约定

- 引擎 `InnoDB`，字符集 `utf8mb4_0900_ai_ci`。
- 主键统一 `id BIGINT UNSIGNED AUTO_INCREMENT`。
- 每表含 `created_at`、`updated_at`（`INT` 秒级时间戳，Yii2 TimestampBehavior）；需软删的表加 `deleted_at INT NULL`。
- 金额统一 `DECIMAL(10,2)`，单位元；或用 `BIGINT` 存分（本文用分，字段名带 `_fen` 后缀的除外，统一用元 DECIMAL）。
- 外键关系在应用层维护（不建物理外键，便于分库与迁移），文档中标注逻辑关系。
- 命名：表名单数下划线（`user`、`shop_order`），布尔用 `is_xxx TINYINT(1)`，枚举用 `TINYINT` + 代码常量。

| nickname | VARCHAR(50) | 昵称 |
| avatar | VARCHAR(255) | 头像 URL |
| gender | TINYINT | 0未知 1男 2女 |

## 10. 索引与性能要点

- `feed`：`(status, created_at)`、`(user_id, created_at)`；关注流用 `follow` join 或 Redis 时间线。
- `product`：`(status, category_id, sales)`、`(shop_id, status)`、`forme_dynasty` + `forme_type` 复合。
- `shop_order`：`(user_id, status, created_at)`、`(shop_id, status, created_at)`、`order_no`。
- `product_review`：`(product_id, created_at)`、`sentiment`。
- 大文本（`detail`、`content`）与主表冷热分离可选；图集/规格用 JSON 列。
- 全文检索（商品标题、攻略、同袍昵称）P1 迁移 Elasticsearch。

## 11. 迁移管理

统一用 Yii2 migration（`yii migrate`）。命名 `m<yymmdd_hhmmss>_create_<table>`。禁止手工改生产库结构；所有 DDL 走 migration 并入 git。
