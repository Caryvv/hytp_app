# 13 AI 与数据服务

> 对应策划案的虚拟试穿/AR 试妆、智能问答、推荐算法、情感分析、"数据采集—多模态分析—场景化策略生成"闭环。独立 Python（FastAPI）微服务，Yii2 通过内网 HTTP 调用。

## 1. 架构定位

```
Yii2 (api/merchant/admin) ──内网HTTP+内部签名──▶ AI 服务 (FastAPI)
                                                   ├─ 试穿/试妆（GPU）
                                                   ├─ 智能问答（LLM+知识库）
                                                   ├─ 推荐（召回+排序）
                                                   └─ 情感分析（NLP）
              埋点/行为 ──▶ 数据管道 ──▶ 特征/向量库 ──▶ 上述服务
```

- 同步能力（问答、推荐、情感）直接 HTTP 返回。
- 重计算（试穿渲染）走**异步任务队列**：Yii2 提交 → 返回 taskId → AI 服务处理 → 回调 Yii2 或客户端轮询。
- 内部调用鉴权：内网 + `X-Internal-Sign`（HMAC，密钥仅服务间共享）。

## 2. 虚拟试穿 / AR 试妆

### 2.1 输入输出
- 试穿 submit：`{ userPhotoUrl | avatarId, productId, garmentImageUrl, sku:{size,color}, accessories:[{type,assetUrl}] }`
- 输出：`{ taskId }`；结果 `{ status: processing|success|failed, resultImageUrl, cost }`
- AR 试妆：`{ userPhotoUrl, makeupStyleId }` → 效果图。

### 2.2 技术方案
- 试穿：基于人体解析 + 服装迁移（如 Diffusion 试衣模型 / VITON 类）；虚拟形象走 3D/2D 素材合成。
- 商品需在商家上架时提供 `tryon_model_url`（去背服装图/建模素材）。
- GPU 实例部署，任务队列（Redis/RabbitMQ）+ worker；超时/失败回退默认展示图并返 1801。

### 2.3 对接接口（Yii2 暴露给客户端）
见 06：`/tryon/submit`、`/tryon/result/{taskId}`、`/tryon/avatars`。

## 3. 智能问答

- 汉服领域知识库（形制、山正区分、身材选款、甲胄合规等）+ RAG：向量检索命中知识 → LLM 生成回答。
- 内部接口 `POST /ai/qa`：`{ question, imageUrl?, audioUrl? }` → `{ answer, hitKnowledge:bool, refs:[] }`。
- 语音转文本（ASR）、图片理解（多模态）可选接入。
- 未命中（`hitKnowledge=false` 且置信低）→ Yii2 引导转「萌新求助」社区。

## 4. 推荐算法

### 4.1 场景
- 首页个性化流、商品"高性价比爆款"、社交内容推荐、同袍精准匹配、文旅季节调度。

### 4.2 方案（分阶段）
- **P0/MVP**：规则 + 热度（销量/点赞/新鲜度加权），冷启动用标签召回。
- **P1**：协同过滤（itemCF/userCF）+ 销量聚类模型（爆款）+ 情感加权。
- **P2**：召回（多路：兴趣标签/协同/热度/地域）+ 排序（LR/GBDT/深度模型），特征来自埋点。

### 4.3 内部接口
- `POST /ai/recommend`：`{ userId, scene, context, size }` → `{ items:[{id,type,score}] }`
- `POST /ai/match`：`{ userId, size }` → 相似同袍列表（基于 `user_profile_tag`）。

## 5. 情感分析

- 触发：`product_review` 新增后异步任务（队列）。
- 内部接口 `POST /ai/sentiment`：`{ texts:[] }` → `[{ sentiment:0|1|2, keywords:[] }]`。
- 关键词抽取聚焦品控词（线头/色差/炸褶/版型/做工），写回 `product_review.sentiment/keywords`。
- 商家驾驶舱 `review-keywords` 聚合这些关键词指导品控。

## 6. 数据闭环（采集—分析—策略）

```
埋点SDK(端) ─▶ 上报接口 ─▶ 行为日志(Kafka/日志表)
   ─▶ 离线/近线计算(每日 data_stat_daily + 特征)
   ─▶ 用户画像/销量预测/热门款式/推荐特征
   ─▶ 回流：首页推荐、商家驾驶舱、管理端监控、运营策略
```

- 埋点事件：曝光、点击、浏览时长、试穿、加购、下单、分享、搜索、停留。
- 用户画像维度：年龄、性别、地域、形制偏好、消费能力、活跃度。
- 销量预测：按商品/品类时序预测，供商家备货。

## 7. 内部接口鉴权与容错

- Yii2 → AI：内网地址 + `X-Internal-Sign`（HMAC-SHA256(body, secret)）+ 时间戳防重放。
- 超时（默认 3s 同步、异步任务另计）→ 降级：推荐回退热度榜、问答回退 FAQ、试穿回退默认图，均返对应 1800 段错误码但不阻断主流程。
- AI 服务无状态可水平扩展；GPU 任务单独伸缩。

## 8. 验收标准

- 试穿异步链路稳定，失败可降级，客户端有明确处理中/失败态。
- 智能问答能命中领域知识并生成回答，未命中可转求助。
- 推荐/匹配接口返回带分值的结果，首页与匹配可用（MVP 规则版即可上线）。
- 评价提交后情感与关键词异步写回，商家端可见关键词聚合。
- AI 服务不可用时主流程不崩溃（降级生效）。
