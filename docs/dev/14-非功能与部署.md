# 14 非功能、安全与部署

> 对应策划案「六、风险控制」「七、发展规划」，以及全平台的安全、性能、合规、运维要求。

## 1. 安全

### 1.1 认证授权
- JWT 三端隔离（`aud=app/merchant/admin`），Refresh Token Redis 白名单，退出即拉黑。
- 后台 RBAC（12），权限点粒度到操作；所有后台写操作记操作日志。
- 越权防护：涉及 `user_id/shop_id` 归属的读写，Service 层强制校验属主。

### 1.2 数据安全
- 密码 `Security::generatePasswordHash`（bcrypt）；敏感字段（手机号）展示脱敏。
- 传输全站 HTTPS/TLS；敏感配置走环境变量，不入库不进 git。
- SQL 全部参数绑定（AR/QueryBuilder），富文本过滤 XSS，上传文件校验类型/大小/前缀。
- 支付回调验签、幂等；金额服务端计算，不信任客户端传入价格。

### 1.3 风控
- 短信/登录限流与失败锁定；接口级限流（Nginx + Redis 计数）。
- 内容安全：动态/评论/攻略过敏感词 + 人工审核；图片鉴黄（可接三方）。

## 2. 合规（对齐策划案风险控制）

| 风险 | 措施 |
|------|------|
| 版权（山品/盗用原创） | 商家资质审核、原创证明、版权协议；版权投诉通道；违规下架处罚；定期排查 |
| 商家履约 | 信用体系 + 保证金；真实评价公示；客诉介入调解、保证金赔付；租赁纠纷规则 |
| 用户流失 | 差异化功能、内容更新、社群运营、短视频平台引流 |
| 行业波动 | "汉服+"多元场景；甲胄等敏感品合规售卖与宣传；舆情监测 |
| 甲胄合规 | 甲胄内容加安全/合规提示，佩戴规范科普，敏感品规范售卖 |
| 隐私 | 个人信息收集最小化、隐私协议、注销、数据导出（合规要求） |

## 3. 性能

- 热点缓存 Redis（首页推荐、科普、商品详情、形制字典）。
- 图片/视频 OSS + CDN，客户端缩略图样式；大文本冷热分离。
- 社交 Feed 时间线 Redis ZSet；分页游标化（避免深分页 offset）。
- DB 读写分离（P1）、慢查询监控、关键表索引（见 02 §10）。
- 客户端：Paging3 分页、Coil 缓存、列表复用、启动优化。

## 4. 可观测性

- 日志：Yii2 分级日志（error/warn/info），关键业务（下单/支付/赔付/审核）审计日志。
- 监控：接口 QPS/耗时/错误率、DB/Redis/队列、AI 服务健康；告警（异常订单、支付失败、AI 超时）。
- 异常：统一异常处理，未捕获异常兜底为 5000 段错误码并告警，不向用户暴露堆栈。

## 5. 部署拓扑

```
                 ┌───────────── CDN (静态/图片/视频) ─────────────┐
用户 ─▶ DNS ─▶ Nginx(负载均衡/TLS/限流)
                 ├─▶ Yii2 api      (PHP-FPM 多实例)
                 ├─▶ Yii2 merchant
                 ├─▶ Yii2 admin
                 ├─▶ Vue 静态站(merchant/admin 前端)
                 └─▶ AI 服务(FastAPI, GPU 节点)
后端 ─▶ MySQL(主从) / Redis(主从或集群) / OSS / 消息队列
console: 定时任务(数据快照/会员到期/清理) + 队列 worker(试穿/情感/推送)
```

- 容器化（Docker）+ 编排（Compose/K8s 视规模）；环境 dev/test/prod 隔离。
- 数据库变更走 Yii2 migration，禁止手工改生产库。
- 定时任务（console）：`data_stat_daily` 生成、会员到期处理、Refresh Token 清理、异步任务补偿。

## 6. CI/CD

- 代码仓库分支：`main`(prod) / `develop`(test) / feature 分支；PR 合并前跑测试。
- 后端：PHPUnit + 静态检查（Psalm/PHPStan）；前端：单测 + lint；Android：单测 + Compose UI 测试 + ktlint。
- 构建产物：Android APK/AAB 签名发布；Yii2 部署包；Vue 打包静态；AI 镜像。

## 7. 里程碑（对齐策划案发展规划）

| 阶段 | 时间 | 目标 | 交付模块（P0/P1） |
|------|------|------|-------------------|
| 短期 | 1–3 月 | 上线 MVP，种子用户 10万+，商家 200+，交易额 50万+ | 账号、萌新入门(科普/试穿)、交易区、基础社交、商家店铺、管理端审核 |
| 中期 | 4–6 月 | 用户 50万，活跃 30%+，商家 500+，交易额 300万+ | 社群/匹配、文旅、文化、数据驾驶舱、营销、情感分析 |
| 长期 | 7–12 月 | 用户 100万，商家 1000+，交易额 1000万+ | AR 试妆、定制共创、供应链、推荐进阶、自有品牌、开放生态 |

## 8. 验收标准

- 全站 HTTPS，敏感配置不落库不进 git，越权/限流/幂等生效。
- 合规措施（资质审核、保证金、版权投诉、甲胄提示、隐私注销）落地可用。
- 关键链路有日志与告警，异常不暴露堆栈。
- 三端可独立部署与灰度，DB 变更全走 migration。
- MVP 阶段 P0 模块全部可用并通过各模块文档的验收标准。
